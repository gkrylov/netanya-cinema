# Кино в Нетании

**Сайт:** https://gkrylov.github.io/netanya-cinema/ (обновляется сам:
каждый день в 7:00 и в четверг в 20:00 по израильскому времени, круглый год).

Личное приложение для отслеживания того, что идёт в **Cinema City Netanya**
на ближайших выходных (пятница и суббота), с возможностью смотреть любые
другие даты.

## Зачем

Сайт Cinema City показывает расписание неудобно: только на иврите, по одному
дню, без оригинальных названий, страны и года, без рейтингов. Хочется одним
взглядом понять: какие фильмы идут в выходные, в какое время, в Prime или
в обычном зале, на каком языке, и что это вообще за фильм.

## Что умеет (цель)

- **Расписание на дату или на выходные.** Для каждого сеанса: время, фильм,
  зал (Prime или пусто), язык показа.
- **Карточка фильма.** Английское и оригинальное название, название на иврите, год,
  страна, язык оригинала, жанр, длительность, возрастное ограничение,
  дата премьеры в Израиле, краткое описание.
- **Заметки.** Что уже посмотрели, оценка, впечатления; в расписании
  такие фильмы отмечены `✓ watched`.
- **Рейтинги и деньги:** IMDb, Rotten Tomatoes (критики и зрители), бюджет и сборы.
- **Позже:** актёры и режиссёры,
  трейлеры, фильтры («только Prime», «без дубляжа»,
  «после 19:00»), история показов, сравнение с другими кинотеатрами.

## Как устроено

Три слоя, каждый можно менять независимо:

1. **Сбор.** Скрипт забирает данные у Cinema City (и позже у внешних
   источников вроде TMDB) и складывает в локальные файлы.
2. **Хранение.** Обычные Markdown-файлы с YAML-шапкой: читаются глазами,
   правятся руками, лежат в git. Два вида файлов: **фильм** и **день**.
3. **Визуализация.** Статическая HTML-страница, собранная из этих файлов.
   Сначала открывается локально, потом становится сайтом.

Подробный план по этапам в [PLAN.md](PLAN.md).

## Источник данных

С 06.10.2026 сайт cinema-city.co.il сделан на Wix. Свои данные он загружает
из коллекций Wix Data; сборщик (`scripts/cinema_city.py`) читает их так же,
как браузер анонимного посетителя:

1. `GET /_api/v1/access-tokens` → публичный токен посетителя
   (`apps["675bbcef-18d8-41f5-800e-131ec9e08762"].instance`, приложение Wix Code);
2. `POST /_api/cloud-data/v2/items/query` с этим токеном в `Authorization`.

| Коллекция | Что в ней |
|---|---|
| `SyncPresentations` | сеансы всей сети: `dateTime`, `businessDate` (ночные сеансы относятся к предыдущему дню), `featureId`, `featureName`, `featureAdditionalName` (англ.), `locationName` (`סינמה סיטי נתניה`), `venueTypeName` (`רגיל` / `Prime` / VIP / Lounge / ONYX), зал, язык и дубляж (`dubbedLanguageISO` в `payloadJson`), длительность, `soldout`, `externalId` (номер сеанса) |
| `SyncFeatures` | фильмы: `externalId` (= номер в адресе `/movie/<номер>`), название на иврите, `additionalName` (англ.), `dateStarted` (премьера), длительность, жанр, возраст, описание |

Ссылка на покупку билета: `https://tickets.cinema-city.co.il/order/<номер сеанса>`.

До 06.10.2026 у сайта были JSON-запросы `/tickets/Events` и др. (теперь 404);
номера фильмов на новом сайте другие, старые остались в карточках в `cc_movie_id`.

**Все данные хранятся на английском.** Русских названий нет.

**Язык показа** это язык звуковой дорожки в зале: `dubbed` (дубляж на
иврит; сайт отдаёт язык дубляжа полем, в названии приписка `-מדובב`),
изредка `dubbed (Russian)` или `dubbed (French)`,
иначе основной язык фильма по TMDB, а остальные его языки в скобках:
`English (+Hungarian, Italian)`. Эти куски в Израиле идут с ивритскими
субтитрами. `Hebrew` и `dubbed` это разные значения: первое значит
израильский фильм в оригинале, второе значит иностранный фильм
с ивритской озвучкой.

**Чего у Cinema City нет:** страны, года, оригинального языка, актёров,
рейтингов. Это берём из других источников:

| Что | Откуда |
|---|---|
| Английское и оригинальное название, год, страна, языки, жанры, описание | TMDB API, поиск по названию |
| Бюджет и мировые сборы (`budget_usd`, `revenue_usd`) | TMDB; у новых и небольших фильмов часто пусто |
| Рейтинг IMDb и число голосов | официальный файл IMDb `title.ratings.tsv.gz` (datasets.imdbws.com), кэш в `data/cache/`, перекачивается раз в сутки. Сам сайт IMDb скрипты не пускает |
| Сцены во время и после титров (`credits_during`, `credits_after`: yes / no / нет поля = неизвестно) | aftercredits.com (открытый WordPress API); запасной источник: метки TMDB. Описания сцен не копируются (чужой текст, сайт публичный): на странице только ссылка «What happens (spoilers)», открывается по клику |
| Rotten Tomatoes: критики (Tomatometer) и зрители (Popcornmeter) | страница фильма на rottentomatoes.com, найденная поиском по названию и году |

Рейтинги и деньги меняются, поэтому обновляются при каждом сборе;
остальная карточка создаётся один раз.

Доступ к TMDB хранится в `.env` (`TMDB_READ_TOKEN`,
запасной вариант `TMDB_API_KEY`), файл в `.gitignore`.

## Как пользоваться

```
python3 scripts/fetch_schedule.py              # ближайшие выходные (пт + сб)
python3 scripts/fetch_schedule.py 2026-10-02   # конкретные даты
python3 scripts/fetch_movie.py 6123 --refresh  # пересобрать карточку фильма
python3 scripts/fetch_ratings.py               # обновить рейтинги во всех карточках
python3 scripts/fetch_credits.py               # проверить сцены после титров
python3 scripts/serve.py                       # собрать страницу и открыть на localhost:8000
```

Если Cinema City ещё не выложил расписание на нужные даты, сборщик
пустых дней не создаёт, а записывает в `data/availability.md`, до какого
дня расписание выложено; страница показывает это вместо пустого списка.

Страницу надо открывать через `serve.py`: открытая с диска (`file://`),
она не может загрузить файлы с данными.

Нужен только Python 3, внешних пакетов нет. Карточки фильмов создаются
один раз и потом не перезаписываются (кроме списка версий), так что
ручные правки в них сохраняются. Карточки с `needs_review: true`
сопоставлены с TMDB неуверенно, их надо проверить.

## Код и данные раздельно

- **Код** (этот репозиторий, публичный, `gkrylov/netanya-cinema`):
  сборщики, страница, документация, workflow робота.
- **Данные** (`data/`, отдельный закрытый репозиторий
  `gkrylov/netanya-cinema-data`, в репозитории кода игнорируется):
  расписания, карточки, заметки. Другой путь к данным
  можно задать переменной `MOVIES_DATA`.
- **Страница** (`web/`) это только код: при открытии она загружает JSON
  из `data/` рядом с собой. JSON делается из Markdown (`export_json.py`)
  и в git не хранится. `build_public.py` складывает код страницы и JSON
  в `public/`: её отдаёт локальный сервер и потом будет публиковать
  GitHub Pages.
- **Кэш** (`.cache/`, файл рейтингов IMDb) ни там, ни там.

## Автообновление

`.github/workflows/update.yml` в репозитории кода (GitHub Actions):

- **по расписанию**: робот просыпается каждые полчаса (минуты :07 и :37),
  `scripts/due.py` проверяет по израильскому времени, наступил ли срок
  (7:00 ежедневно, четверг 20:00) и был ли уже сбор после него. Если срок
  наступил: сбор → коммит в репозиторий данных → сборка → публикация.
  Иначе запуск сразу завершается. Так задержки GitHub (на начале часа
  бывало 5–7 часов) почти не мешают, а зимнее время сроки не сдвигает;
- **по кнопке** «Run workflow»: сбор и публикация;
- **при изменении кода** (push в `main`): только сборка и публикация;
- вручную без сбора: `gh workflow run update.yml -R gkrylov/netanya-cinema -f collect=false`.

Секреты репозитория кода: `TMDB_READ_TOKEN` и `DATA_DEPLOY_KEY`
(закрытая часть ключа развёртывания репозитория данных с правом записи).

```
Movies/                     репозиторий кода
├── README.md               описание (этот файл)
├── PLAN.md                 план работ и статус
├── CLAUDE.md               правила проекта для Claude
├── .github/workflows/      робот: сбор и публикация
├── scripts/                сбор, экспорт в JSON, сборка и локальный сервер
├── web/                    код страницы: index.html, app.js, style.css
├── data/                   репозиторий данных (отдельный git)
│   ├── days/               один файл на день:    2026-09-26.md
│   ├── movies/             один файл на фильм:  spider-man-brand-new-day-2026.md
│   └── watched.md          заметки: что посмотрели
├── public/                 собранная страница + JSON (не в git)
└── .cache/                 файл рейтингов IMDb (не в git)
```
