# Кино в Нетании

Расписание Cinema City Netanya на выходные + карточки фильмов.
Описание и источники данных в [README.md](README.md), план и статус
этапов в [PLAN.md](PLAN.md). Читать оба перед работой.

## Правила данных

- Все данные в файлах **на английском**: названия, страны, языки, жанры,
  описания, заметки, заголовки таблиц. Русских названий не хранить.
  **Исключение: досье (`data/dossiers/`) пишутся по-русски** (просьба пользователя 08.10.2026).
  Общение с пользователем по-русски.
- Колонка Hall: `Prime` или пусто. Никаких «regular».
- Язык показа: `dubbed` (дубляж на иврит) и `Hebrew` (израильский фильм)
  это разные значения. Остальные языки фильма в скобках: они идут
  с ивритскими субтитрами, а пользователь читает на иврите медленно.
- Посмотренное и отзывы пользователя живут в `data/watched.md`
  (строка `movie: <slug>`), не в карточках. Такие фильмы в расписании серые.
- Карточки фильмов создаются один раз, ручные правки в них не затирать.
  Рейтинги и деньги обновляются при каждом сборе.
- Сцены после титров (`credits_during`/`credits_after`, `fetch_credits.py`):
  ответ aftercredits.com окончательный, `credits_source: manual` не трогать.
  Спойлеры не показывать открытым текстом: только по явному клику (ссылка).
  Пользователю важен только факт «оставаться ли»: mid-credits / end, без количества.
  Википедия и TMDB дают только «да»; «нет» бывает лишь от aftercredits.com.
- Описания сцен после титров: `data/scenes.md` (раздел на фильм, `movie: <slug>`),
  пишет Claude по-русски своими словами, весь сюжет сцен под `||спойлером||`.
  Делать для фильмов из расписания, где сцены есть (по просьбе или вместе с досье);
  чужой текст не копировать, можно отметить, стоит ли ждать (оценка зрителей aftercredits).

## Архитектура

- **Код и данные не смешиваются**, ни в репозитории, ни в одном файле.
- `data/` это **отдельный git-репозиторий** (в репозитории кода в `.gitignore`).
  Изменения данных (заметки, расписание) коммитить в нём: `git -C data ...`.
  Код коммитить в корневом репозитории. Никогда не добавлять данные в код.
- Страница (`web/`) только код, данные грузит сама из `data/*.json`.
  JSON и `public/` производные, в git не хранятся.

## Сайт и робот

- Сайт: https://gkrylov.github.io/netanya-cinema/ . Код: `gkrylov/netanya-cinema`
  (публичный, ничего личного туда не класть). Данные: `gkrylov/netanya-cinema-data`
  (закрытый). Робот (`.github/workflows/update.yml`) сам собирает и коммитит данные.
- **Добавить заметку** о просмотренном: `git -C data pull`, дописать
  `data/watched.md`, `git -C data commit` и `push`, затем опубликовать без сбора:
  `gh workflow run update.yml -R gkrylov/netanya-cinema -f collect=false`.
- **Пометить фильм как интересный**: дописать раздел в `data/interesting.md`
  (`## Title (year)`, `movie: <slug>`, `added: <дата>`), коммит и push в данных,
  публикация без сбора (как с заметкой).
- **Досье на фильм** (`data/dossiers/<slug>.md`, только по просьбе пользователя,
  само не обновляется): шапка `updated: <дата>`, дальше Markdown **по-русски**
  (`##` разделы, списки, **жирный**, ссылки). Собирать поиском в интернете
  (WebSearch), пересказывать своими словами, цитаты не длиннее одной короткой
  фразы, источники ссылками. Разделы по умолчанию:
  Название (по-русски, по-английски, на иврите), **Где снимали (всегда)**,
  После титров (есть ли сцены; описание своими словами под `||спойлер||`), Release (мир, Израиль, ожидаемый конец основного проката), Cast (и где
  пользователь мог их видеть: сверять с `watched.md`), Critics and audiences,
  Related films (приквелы и т. п.), Trivia, Russia (идёт ли в прокате;
  есть ли в расписании «Киномакс-Солярис»: Москва, Перерва 43 к1, ТК «Бум»,
  расписание на afisha.ru/msk/cinema/kinomaks-solyaris-3089/, грузится скриптом,
  смотреть во встроенном браузере). Спойлеры в досье только как `||текст||`
  (на сайте скрыты до нажатия).
- Перед любой правкой данных сначала `git -C data pull`: робот коммитит туда сам.
- Изменения кода: коммит и `git push` в репозитории кода, сайт пересоберётся сам.
- Робот просыпается каждые 30 минут; собирать или нет, решает `scripts/due.py`
  (сроки 7:00 ежедневно и четверг 20:00 по Израилю; последний сбор берётся
  из `data/availability.md`).

## Источник и прозрачность

- Cinema City читается из коллекций Wix (`scripts/cinema_city.py`), подробности
  в README. Если сайт снова поменяется, чинить надо этот модуль.
- Каждая попытка сбора пишет итог в `data/status.md`; страница показывает
  красное предупреждение при ошибке и если успешного сбора не было 30 часов.
  Ошибку никогда не глотать молча: сайт публикуется с предупреждением, запуск
  робота помечается упавшим.

## Как запускать

```
python3 scripts/fetch_schedule.py              # ближайшие выходные (пт + сб)
python3 scripts/fetch_schedule.py 2026-10-02   # конкретные даты
python3 scripts/fetch_ratings.py               # только рейтинги
python3 scripts/serve.py                       # собрать public/ и открыть localhost:8000
python3 scripts/build_public.py                # только собрать public/
```

Интерфейс страницы на английском. «Hide watched» включён по умолчанию.
Все даты и «сейчас» считаются по `Asia/Jerusalem` (`now_il()` в common.py).

Только стандартная библиотека Python 3. Доступ к TMDB в `.env`
(`TMDB_READ_TOKEN`), содержимое `.env` не выводить.
Сайт IMDb блокирует скрипты: рейтинг берётся из официального файла
datasets.imdbws.com, обходить защиту сайта не надо.
