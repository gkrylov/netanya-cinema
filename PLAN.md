# План

**Статус на 29.09.2026:** этапы 1–3 готовы. Сайт:
https://gkrylov.github.io/netanya-cinema/ , обновляется сам.

Выходные в Израиле: пятница и суббота. «Ближайшие выходные» считаются так:
если сегодня пятница или суббота, это сегодня и (если пятница) завтра;
иначе ближайшие пятница и суббота. Сеансы после полуночи (например,
`26/09 00:15` в пятничном списке) относятся к дню, в который их показывает
сайт, то есть к пятнице.

## Этап 1. Сбор и локальное хранение ✅

### 1.1. Формат файлов

Все данные в файлах хранятся **на английском** (названия, страны, языки,
жанры, описания). Русских названий нет. Название на иврите остаётся
для сопоставления с сайтом Cinema City.

**Файл дня** `data/days/2026-09-26.md`: расписание на одну дату.

```markdown
---
date: 2026-09-26
weekday: Saturday
cinema: Cinema City Netanya
fetched_at: 2026-09-25T14:05:00+03:00
sessions_count: 63
sessions:
  - {"time": "10:00", "movie": "coyote-vs-acme-2026", "prime": true, "screen_language": "dubbed", ...}
---

# Saturday, 26 September 2026

| Time | Movie | Hall | Language | Ratings |
|---|---|---|---|---|
| 10:00 | [Coyote vs. Acme](../movies/coyote-vs-acme-2026.md) · 2026, USA | Prime | dubbed | IMDb 7.5 · RT 96% |
| 19:10 | [Before We Leave Tuscany](../movies/before-we-leave-tuscany-2026.md) · 2026, Hungary, USA · ✓ watched |  | English (+Hungarian, Italian) |  |
```

- **Hall:** `Prime` или пусто (обычный зал).
- **Language:** `dubbed` (дубляж на иврит), `dubbed (Russian)`, иначе
  основной язык фильма по TMDB; остальные языки фильма в скобках
  (в зале они идут с ивритскими субтитрами).
- **Time** это ссылка на покупку билета: `https://tickets.cinema-city.co.il/order/<event_id>`
  (сайт перенаправляет на tickets.cinema-city.co.il). В шапке она же в `ticket_url`.
- Сеансы после полуночи помечены `(night)` и относятся к предыдущему дню.
- Прошедшие сеансы остаются в файле; отменённые помечены `(removed)`.
- `✓ watched`: фильм есть в `data/watched.md`; такие строки приглушены серым
  (`<span style="color:gray">`, работает там, где Markdown показывает HTML-стили).

**Файл фильма** `data/movies/before-we-leave-tuscany-2026.md`: всё о фильме.

```markdown
---
slug: before-we-leave-tuscany-2026
cc_movie_id: [6318]          # все версии фильма у Cinema City (дубляж, англ.)
title_he: להתאהב בטוסקנה
title_en: Before We Leave Tuscany
title_original: Egy nő sziluettje
year: 2026
country: [Hungary, USA]
original_language: Hungarian
spoken_languages: [English, Hungarian, Italian]   # первый = основной
genre: [Romance, Drama]
runtime_min: 91
age_rating: all ages
premiere_il: 2026-09-17
dubbed_available: false
tmdb_id: 1438212
imdb_id: tt34547698
imdb_rating:                 # рейтинги и деньги обновляются при каждом сборе
imdb_votes:
rt_critics:                  # Tomatometer, %
rt_audience:                 # Popcornmeter, %
rt_url:
budget_usd:
revenue_usd:                 # мировые сборы по TMDB
ratings_checked: 2026-09-25
needs_review: false
sources_checked: 2026-09-25
---

# Before We Leave Tuscany (2026)

*Egy nő sziluettje*

Overview from TMDB (English).
```

Слаг: английское название + год. Одна карточка на фильм: все версии
(дубляж, английская, русский дубляж) это разные `MovieId` у Cinema City,
они собираются в одну карточку по TMDB или по названию на иврите.

**Файл заметок** `data/watched.md`: что посмотрели и что думаем.
Один раздел на просмотр, строки `movie: <slug>`, `watched: <дата>`,
`rating: 1–10`, дальше свободный текст на английском.

### 1.2. Скрипт сбора расписания

> С 06.10.2026 источник другой (коллекции Wix, см. README и раздел
> «Инцидент 06.10.2026» ниже); шаги ниже описывают исходную версию.

`scripts/fetch_schedule.py [дата ...]` (без аргументов: ближайшие выходные)

1. Получить список доступных дат (`GetDatesByTheater`).
2. Для каждой нужной даты сделать два запроса `Events`: `VenueTypeId=1`
   и `VenueTypeId=4` (Prime). ⚠️ Запрос с `1` отдаёт **все** сеансы,
   включая Prime, поэтому Prime определяется по совпадению `EventId`
   со вторым списком.
3. Разобрать название: отрезать суффикс `-מדובב`, определить язык показа.
   Язык показа это одно поле: `dubbed`, если есть суффикс, иначе
   основной язык фильма из карточки (`English`, `Hebrew`...).
   `Hebrew` и `dubbed` не путать. Встречающиеся суффиксы:
   `-מדובב` (дубляж на иврит), `-מדובב לרוסית` (дубляж на русский),
   `-אנגלית` (английская версия), `-Infinity Vision` (формат, не язык),
   приставка `G Kids -` (детская программа).
4. Сопоставить с файлом фильма; если его нет, создать (1.3).
   Для всех фильмов из расписания обновить рейтинги и деньги (1.5).
5. Записать файл дня, **сохранив сеансы из прежней версии файла**.
   Сайт убирает сеанс, как только он начался, поэтому исчезнувший
   прошедший сеанс просто остаётся в файле. Если сеанс исчез до своего
   начала, это отмена: `status: removed`, в таблице пометка `(removed)`.

### 1.3. Скрипт карточки фильма

`scripts/fetch_movie.py <MovieId>`

1. Страница `/movie/{MovieId}`: названия иврит/английский, жанр,
   длительность, премьера, возраст, описание.
2. TMDB (бесплатный API-ключ): поиск по английскому названию и году
   премьеры → оригинальное название, год, страна, язык оригинала,
   `tmdb_id`. Если совпадений несколько или ни одного, оставить поля
   пустыми и пометить `needs_review: true`.
3. Создать файл фильма; существующие поля, исправленные руками,
   не затирать.

### 1.4. Заметки

`data/watched.md` ведётся руками (или со слов пользователя): что посмотрели,
отзыв на английском, дата и оценка по желанию. Фильмы оттуда в расписании
серые и с пометкой `✓ watched`.

### 1.5. Рейтинги и деньги

`scripts/fetch_ratings.py [slug ...]`: IMDb (официальный файл
`title.ratings.tsv.gz`, кэш в `data/cache/`), Rotten Tomatoes (критики
и зрители, поиск по названию и году), бюджет и мировые сборы из TMDB.
Обновляются при каждом сборе.

**Результат этапа:** папка `data/` с файлами дней, карточками фильмов
и заметками; одна команда для обновления.

### Открытые вопросы

- Номера залов пока не собираем, различаем только Prime / обычный.
- Показывать ли 3D/ScreenX/4DX, если встретятся в названиях.

## Этап 2. Визуализация ✅

Статическая страница `site/index.html`, собранная скриптом
`scripts/build_site.py` из файлов `data/` (данные встраиваются в страницу,
сервер не нужен: открыть в браузере двойным щелчком). Пересобирается
в конце `fetch_schedule.py`. Интерфейс на английском, как и данные.

**Первая очередь**

1. **Экран «Выходные».** Две колонки (пятница, суббота), сеансы по времени.
   У сеанса: время крупно, название (английское), год и страна мелко,
   значок Prime (у обычного зала ничего), язык (`English (+Hungarian,
   Italian)`, `dubbed`), IMDb и RT.
   - Клик по времени → покупка билета (`ticket_url`).
   - Посмотренные фильмы (`data/watched.md`) приглушены серым.
   - Прошедшие сеансы бледнее, отменённые (`status: removed`) зачёркнуты.
2. **Карточка фильма** по клику на название: названия (англ., оригинал,
   иврит), год, страны, жанры, длительность, возраст, описание, IMDb
   с числом голосов, RT критиков и зрителей, бюджет и сборы, все сеансы
   на выходных со ссылками на билеты, заметка из `watched.md`.
3. **Фильтры** (запоминаются в браузере): только Prime; скрыть посмотренное
   (**включено по умолчанию**); скрыть прошедшее; язык (без дубляжа / без ивритских субтитров,
   то есть только английский без других языков / только израильское
   кино); время «после ...»; минимальный IMDb.
4. **Выбор даты** из тех, для которых есть файлы дней.

**Вторая очередь**

5. **Вид «по фильмам»:** список фильмов, у каждого в строку все его
   сеансы за выходные; сортировка по рейтингу.
6. **Лента времени:** горизонтальная ось часов, строка на фильм, полоска
   на сеанс длиной в длительность фильма (реклама перед началом не учтена),
   Prime выделен цветом, красная линия «сейчас». Пересекающиеся сеансы
   одного фильма раскладываются по дорожкам. Видно, что влезает в вечер
   и можно ли успеть на два фильма подряд.

**Результат этапа:** страница, где за 10 секунд понятно, куда пойти
в выходные.

## Этап 3. Сайт с автообновлением ✅

**Цель:** сайт по постоянной ссылке (с телефона тоже), расписание
обновляется само, без Mac.

### Принцип: код, данные и сборка не смешиваются

Ни один файл не содержит одновременно код и данные.

| Что | Где живёт | Кто меняет | В git |
|---|---|---|---|
| Код сбора, код страницы, документация | репозиторий **кода** | Claude, по просьбам | да |
| Данные в Markdown (дни, карточки, `watched.md`) | репозиторий **данных** | робот (сбор), пользователь через Claude (заметки) | да, отдельная история |
| JSON для страницы | делается из Markdown при каждом сборе | скрипт | нет |
| Кэш (IMDb) | локально / в кэше робота | скрипт | нет |

### Два репозитория на GitHub (аккаунт `gkrylov`)

1. **Код** (`netanya-cinema`, рабочее название): `scripts/`, код страницы,
   документация, инструкция для робота. Ничего личного, может быть
   публичным (это нужно для бесплатного GitHub Pages).
2. **Данные** (`netanya-cinema-data`): `days/`, `movies/`, `watched.md`.
   Закрытый. История коммитов = история расписания и просмотров.

**На Mac:** папка `data/` становится отдельным git-репозиторием
внутри проекта; репозиторий кода её игнорирует (`.gitignore`). Раскладка
папок и Obsidian не меняются. Путь к данным скрипты берут из переменной
`MOVIES_DATA`, по умолчанию `data/`.

### Страница: только код, данные грузит сама

- Код страницы: `web/index.html`, `web/app.js`, `web/style.css`.
  Не меняются при обновлении расписания. Данные в них не вклеиваются.
- При открытии страница загружает JSON:

  ```
  data/index.json           список дат, время последнего сбора
  data/days/<date>.json     сеансы дня
  data/movies.json          карточки фильмов (с рейтингами)
  data/watched.json         посмотренное
  ```

- JSON делает `scripts/export_json.py` из Markdown после каждого сбора.
  Источник правды остаётся в Markdown (читается и правится в Obsidian).
- `build_site.py` со вклейкой данных и `site/index.html` удаляются.

- `scripts/build_public.py` собирает `public/` = `web/` + `public/data/*.json`
  (не в git). Её же будет публиковать GitHub Pages.

**Локально:** страницу, открытую с диска (`file://`), браузер не пускает
к соседним файлам. Поэтому `python3 scripts/serve.py`: собирает `public/`
и открывает `http://localhost:8000`.

### Автообновление: GitHub Actions

Инструкция `.github/workflows/update.yml` в репозитории кода:

1. По расписанию (частота: открытый вопрос) и по кнопке вручную.
2. Берёт репозиторий кода и репозиторий данных (доступ к закрытым
   данным по отдельному ключу с правом записи только в этот репозиторий).
3. Запускает сбор: расписание, карточки, рейтинги.
4. Коммитит изменения в репозиторий данных.
5. Делает JSON, кладёт рядом с кодом страницы и публикует в GitHub Pages
   напрямую (деплой из Actions, без коммита собранного сайта в git).

- Токен TMDB в секретах GitHub (`TMDB_READ_TOKEN`); скрипт берёт его
  из `.env` или из переменной окружения.
- Все «сегодня», «ближайшие выходные», «прошедший сеанс» считаются
  по времени `Asia/Jerusalem`, а не по UTC сервера.
- Файл IMDb хранится в кэше Actions между запусками.

**Заметки:** пользователь рассказывает, Claude правит `watched.md`
в репозитории данных, забирает перед этим коммиты робота (`git pull`),
отправляет. Сайт обновится при ближайшей публикации (или запустить
вручную).

### Риски

- **Иностранный адрес.** Серверы GitHub в США; Cinema City или
  Rotten Tomatoes могут не отвечать им. Проверяется первым запуском.
  Запасной вариант: сбор по расписанию на Mac (`launchd`, израильский
  адрес) с отправкой данных в GitHub; публикация по-прежнему через
  Actions. Минус: Mac должен быть включён.
- **Публичность страницы.** Сайт на бесплатном GitHub Pages открыт
  всем, у кого есть ссылка, даже если данные в закрытом репозитории.

## Инцидент 06.10.2026: Cinema City сменил сайт

Сайт переехал на Wix, старые JSON-запросы стали отвечать 404, робот падал,
а страница молча показывала старые данные. Сделано:

- сборщик читает коллекции Wix `SyncPresentations` и `SyncFeatures`
  (`scripts/cinema_city.py`), дубляж берётся из поля языка, ссылки на билеты
  `tickets.cinema-city.co.il/order/<номер>`, номер зала сохраняется в данных;
- прозрачность: итог каждой попытки в `data/status.md`, на странице красное
  предупреждение при ошибке и при отсутствии обновлений больше 30 часов;
  при ошибке робот публикует сайт с предупреждением и помечает запуск упавшим.

Открыто (решение 07.10.2026: пока наблюдаем, ничего не меняем):
- GitHub запускает робота по расписанию «по возможности»: за 5–7.10 было
  8 запусков вместо ~94, сбор за 7:00 приходил с опозданием до ~4 часов.
  Если понадобится точность: внешний будильник (cron-job.org с токеном
  только на запуск workflow, или launchd на Mac) + GitHub cron как запасной.
- 06.10 публикация зависла в «waiting» и держала общую очередь; снята
  принудительной отменой (`gh api -X POST .../runs/<id>/force-cancel`).
  Если повторится: вынести публикацию из общей очереди и добавить сторож,
  отменяющий публикации, висящие дольше 20 минут.
- Контроль: в шапке сайта время последнего успешного сбора, при ошибке
  или если обновлений нет больше 30 часов, красное предупреждение.
